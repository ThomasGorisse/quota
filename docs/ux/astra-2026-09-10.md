# Quota — glance redesign, 2026-09-10

**Historical WIP handoff.** The statements below describe the original September source-only
pass. See [the October completion report](pass2-2026-10-21.md) for the rebase, current
implementation, build results and capture limitations.

Source edits only. No app, test, compiler, browser preview, emulator, Liquid renderer or
screenshot was run. This is an implementation ready for human build and visual review,
not a claim of screenshot validation or measured two-metre/one-second readability.

## Direction and references

Keep the gauge; give it one job. A provider's most-used window is its headline. Smaller
surfaces choose the most-used window across providers. The window label makes the selection
explicit, including when it changes. Percentages cannot establish how many hours of work
remain, so the UI does not make that promise.

Apple describes widgets as a way to see current information, including battery levels, at a
glance; its Weather widget is a useful reference for choosing the context of that reading.
I used that as a reason to remove competing visual structures and keep a named headline.
References: [Apple widgets](https://support.apple.com/en-ie/guide/iphone/iphb8f1bf206/ios),
[Weather widgets](https://support.apple.com/en-ie/guide/iphone/iph8bf15cb61/ios).

Google's At a Glance prioritizes relevant information on the home and lock screens. My
application here is to select the constraint that matters now, while preserving its label.
[Google At a Glance](https://support.google.com/pixelphone/answer/14884067?hl=en).

Fitness rings represent three distinct activity goals. I kept a readable circular proportion
but rejected copying multiple equal rings for every quota window: Quota has one immediate
question, not several goals to close. [Apple Activity rings](https://developer.apple.com/design/human-interface-guidelines/activity-rings).

TRMNL's public framework and Weather example establish the constrained display context and
layout variations. Quota keeps the standard title bar but makes severity a black-and-white
shape. The `/plugins` page redirected to login; the public recipe and framework references
are available without that account. No reference screenshots or assets were downloaded.
[TRMNL framework](https://trmnl.com/framework),
[Weather example](https://trmnl.com/framework/examples/weather),
[public recipes](https://docs.trmnl.com/go/public-api/recipes-api).

## What I challenged and kept

Challenged: equal visual weight for all windows; a privileged 5 h session; special treatment
for Reserve; plan badges; always-visible charts; Watch as a miniature list; filled desktop
height; permanently allocated provider cards; implicit mode/units; keeping an old reading
coloured to make it appear healthy.

Kept: Quota, provider order, vendored marks, brand colours, severity thresholds, wire USED
percentages, product-wide Left/Used, dark/light palettes, rounded native surfaces, existing
network/pairing/cache mechanisms and capture hooks. The single hero changes when the binding
percentage changes; freezing it to a familiar window would repeat the original defect.

## Exact contributor rules

The normative rules are in [DESIGN.md](../DESIGN.md). In particular:

1. Filter to valid percentages in 0…100; choose greatest USED percentage. Tie: backend window
   order, then Claude/Codex/Gemini order for a global hero. Never assume `session` exists.
2. Keep hero value, window label, reset and severity from that same window. Use its supplied
   label, or its id if blank. Display mode does not participate in selection.
3. Show `32%` with `left` below, or `68%` with `used` below. Inline detail is `Week 32% left`.
   Round used once, then subtract from 100 in remaining mode. Never print a unitless number.
4. Use Ready / Running low / Nearly empty / Out of date for <60 / 60…85 / >85 / stale.
   Never derive severity from the displayed remaining value or round before thresholding.
5. Window label follows the gauge, with the reset immediately following the label. Compact
   phone/web layouts put those two lines beside the gauge. Secondary windows never get rings.
6. Reset text is `Resets in 37 min`, `Resets in 2 h 10 min`, or `Resets in 2 d 14 h`.
   Ceil to minutes, then show the stated units. Past: `Reset due`. Missing: `Reset time unknown`.
7. An omitted provider has no card. A present provider without a valid window is No data.
   No zero defaults, simulated full arcs, session labels, or invented reset durations.
8. E-ink state is redundant text and shape: plain / outlined / black-filled / dashed.
   Everything is black or white. Colour screens use grey for stale values and marks.
9. Compact system accessories are the explicit exception to full visible identity/reset;
   preserve selection identity in accessibility. Stale may replace a tiny reset line.

## Unresolved scope conflict: defect 13

**Failed-provider retention is not fixed.** The only permitted Worker edit is the TRMNL
presentation adapter. Ingestion replaces the snapshot before these renderers see it. An omitted
provider carries neither its old plan/windows nor a reason for absence. The fixed instruction
that omitted providers remain absent also rules out blindly merging client caches.

An optional scope question was raised during this pass; no approval to change ingestion or
the contract was available at the time of writing. A complete solution needs last-successful
provider retention at the ingestion boundary and a per-provider freshness/error signal,
with explicit handling of intentional removal. An entirely failed network refresh already
retains each native client's last snapshot; that is different from a successful response
that omits one provider. No data is fabricated to conceal this limitation.
